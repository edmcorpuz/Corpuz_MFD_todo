# Corpuz — MyFirstDjango Todo

A local Django task manager for the **mid_Exer01** GitHub checkpoint exercise.

## Features

- Create and edit tasks with optional notes and due dates.
- Mark tasks complete or reopen them.
- Filter by all, active, and completed tasks.
- Delete tasks through a confirmation page.
- Responsive interface, accessible form labels, CSRF protection, and automated tests.

## Development environment

- Ubuntu 24.04 under WSL 2
- VS Code with the WSL and Python extensions
- Python 3.12.15 managed by mise
- Django 5.2 LTS (exact installed versions in `requirements.txt`)
- Project directory: `/root/MyFirstDjango`

## Run locally

Open the project in VS Code connected to **WSL: Ubuntu-24.04**. In its terminal:

```bash
cd /root/MyFirstDjango
mise install
mise exec -- python -m venv DjangoENV
source DjangoENV/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Open <http://127.0.0.1:8000/>. For the existing setup, simply activate `DjangoENV` and run the server; do not recreate the environment each time.

If `mise` is not yet activated in your shell, use `$HOME/.local/bin/mise` in place of `mise`.

## Tests

```bash
source DjangoENV/bin/activate
python manage.py check
python manage.py test
```

## Exercise checklist

- `manage.py`, `MyFirstDjango/`, and `todo_list/` are at the repository root.
- `initial.txt` is generated in WSL by `whoami.exe | base64 >> initial.txt`, not typed manually. It is the environment fingerprint required by the exercise; base64 is encoding, not encryption.
- `requirements.txt` is generated by `pip freeze` from `DjangoENV`.
- `.gitignore` contains the exercise's four required patterns plus exclusions for local secrets and the SQLite database.
- Git branch: `main`; initial commit message: `Initial commit`.
- Repository: <https://github.com/edmcorpuz/Corpuz_MFD_todo>

## Scope and security

This is a **single-user local learning project**, not a hosted multi-user service. There is no sign-in or per-user task isolation. Keep the development server bound to localhost; do not expose it to a public network.

No credentials, GitHub tokens, local database, or virtual environment are committed. Development uses a temporary randomly generated Django secret when `DJANGO_SECRET_KEY` is absent. Production mode (`DJANGO_DEBUG=False`) requires an explicit secret and `DJANGO_ALLOWED_HOSTS`; authentication, HTTPS, a production server, and additional deployment hardening would also be needed before hosting.
